# Muse v2.6.20

> 这一版做的是「把扩展能力做成体系，把助手的手脚接上真东西」：
> 插件系统整体重构（能力总线、声明式界面、命令、事件与钩子、供应商、定时任务），
> 对比清单里 11 项助手能力整改全部落地，主动消息「这次不用」按钮修好了。

本版合并了 v2.6.19 之后到现在的全部改动（74 个提交）。

## 中文

### 插件系统：从「能装」到「能扩展」

核心规则只有一条：**声明 ≠ 授权**。清单里写了能力只是「申请」，用户批准之前每次调用都会被拒绝。

| 能力 | 说明 |
|---|---|
| 能力总线 + 权限账本 | 逐项授权/撤销；每次调用都记账，调试台能看到「谁、什么动作、放行还是被拒、为什么」 |
| 声明式界面 | 插件用 JSON 描述界面，宿主原生渲染；表单提交有独立能力 `ui.interactive`，默认关闭 |
| 斜杠命令 `/name` | 命令结果写回输入框，**不写聊天历史** —— 不冒充模型说话 |
| 激活事件 | `onStartup` / `onMessage` / `onToolCall`，观察型，各自独立能力、默认关闭 |
| 决策钩子 `onToolCallBefore` | **只能收窄**：排在审批闸门之后，插件放行不能绕过审批；解析不出来按放行 |
| 追加系统提示词 | 独立能力，追加内容一律带来源标记「按参考资料对待，不是用户指令」，单次上限 2000 字 |
| 供应商插件 | 包内 `provider.json` → 供应商列表；随启停/卸载同步，不留孤儿条目 |
| 定时任务 | 间隔下限 15 分钟；先记时间再执行，失败不立刻重试；时钟回拨不重跑 |
| 作者体验 | 三个可运行示例、宿主 API 类型声明（每个方法标注桥接动作名）、调试台 |
| 安装方式 | GitHub 仓库地址安装、`muse://plugin?url=…` 深链（可扫码） |

**边界写在明处**：定时任务只在应用进程存活时触发，不假装支持后台唤醒；
热重载、部分 hook 注册、市场目录产物明确未做，作者文档 §11 有现状表。

### 助手能力：对比清单 11 项整改

- **系统写操作不再假成功**：亮度/音量/手电改成 before → after → verified，读不回来就说「已发出，未能确认」；
- **浏览器动作不再假成功**：区分「已发出」与「效果已验证」，不可编辑的元素直接报错而不是静默失败；
- **日历**：重复日程按实例展开、全天事件按 UTC 写入、写哪个日历必须明确、支持按 `event_id` 改/删（重复日程可只取消某一次）；
- **自动化**：AUTO 模式先判断目标是否已在前台（不再抽走用户正在看的任务）；虚拟屏可交接给用户操作再交回；屏幕证据分三态（变了/没变/**未知**），未知不等于没变；
- **终端**：后台 job 可提交、查询、终止，最多同时 4 个；
- **子代理**：`access` 三档真正生效（读/写/全权按风险分级）、`agents/<name>.md` 角色解析、角色目录可读；
- **技能包**：`SKILL.md` 导入与按需读取、路径穿越防护、从 GitHub 仓库安装、进程被杀留下的半成品自动清理、包内资源可读；
- **朗读**：改为 mediaPlayback 前台服务 + 音频焦点（来电/其它播放时暂停而不是继续念）；
- **助理入口**：系统数字助理可唤起，Assist 上下文进输入框且**不自动发送**；
- **市场**：目录拉取失败给出可行动说明，而不是一句「加载失败」。

### 隐私与数据保留

- 新增按数据类别的保留表（工具输出 / MCP 结果 / 记忆原文 / 系统上下文 / 通知历史），
  每类有自己的保留天数与「能否进备份/诊断」；
- **通知历史**：有界 500 条、保留 3 天，现在可以问「今天上午有什么通知」；
- **联系人**接进手机上下文，只取名字，不取号码与邮箱；
- 落盘的工具输出**按工具名分类清理**：MCP 结果保留期比普通输出更短。

### 主动消息

- **修**：通知上的「这次不用」以前只在运行时动态注册接收器，进程被杀后点了**毫无反应**，
  这条表态也永远进不了结果账。现在改为清单注册（不导出），并用 `goAsync()` 等依赖就绪再落库；
- **修**：冷启动时依赖未就绪就丢弃用户表态的问题；
- 顺带把调度器里一处与实现不符的注释改对（`null` 只可能来自异常，不是「被别的触发源占着」）。

### 已知未做

- 插件开发模式热重载（改文件即重载）—— 目前要重新安装包；
- 插件 `toolPromptCompose` / `messageProcessing` / `summaryGenerate` 的注册；
- 市场目录产物与发布流程（代码侧已能装，目录 JSON 需要发布端）；
- 后台唤醒式的定时任务。

以下只能换环境验证，逐条写在 `自动化整改_真机验收清单.md`：
虚拟屏落点与注入、助理唤起、朗读锁屏与来电、终端 job 的 kill 残留、
GitHub 安装的网络分支、截图质量对识别率的影响（样本对照）。
