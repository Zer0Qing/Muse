# Muse v1.0.85

本版本集中完成了一轮稳定性、动效规范、AI 对话链路和系统能力重构。

## 重点更新

### 聊天与首页

- 统一首页和聊天页面的进入、退出、展开、收起、滑入和列表动效。
- 移除异常的默认 Ripple 按压遮罩，修复 Tab、卡片和弹层中出现白色按压条的问题。
- 首页 Tasks / Agent / Group 三个 Tab 的切换反馈更加一致。
- 问候语下方增加每日助手总结和近期提醒。
- 每日总结与个性化提醒改为短文本输出，各占一行，避免长文本撑开首页布局。
- 即使读取到旧的长缓存或模型返回异常长文本，也会在展示前进行硬限制和压缩。
- 修复 Mood 标记在正文、推理流和流式恢复场景中的解析与展示。
- 修复任务路由在一次任务结束后错误影响后续普通对话的问题。
- 任务路由页面显示实际 Provider / Model 绑定关系。
- 完善助手资源注入链路，覆盖系统提示、预设消息、工具、Skills、MCP、世界书、Prompt Injection、RAG 和全局记忆等资源。
- 聊天输入栏未配置语音识别 API 时只显示发送按钮；配置实时 ASR API Key 后才显示麦克风按钮。
- 移除聊天输入栏中没有实际使用价值的独立语音对话快捷入口。

### UI 自动化与无障碍

- 统一无障碍服务实现和注册，避免同一个 APK 中出现两份 Muse 服务导致系统授权与应用状态不一致。
- 无障碍服务在系统设置中明确显示为 `Muse UI 自动化`。
- 修复部分设备上系统已开启无障碍，但 Muse 内部仍显示未授权的问题。
- 增强 Android 无障碍服务状态检测，兼容 AccessibilityManager 和系统 Secure 设置两条读取路径。
- UI 自动化页面支持完整纵向滚动。
- 无障碍读屏、点击、滑动、输入和权限状态反馈保持同一服务实例。
- Shizuku 不可用时不再伪造自动化成功状态，并提供真实诊断结果。

### 通知监听

- 增加应用名称、通知渠道、类别、分组、优先级、可见性和移除状态等信息。
- 支持活跃通知、历史通知、未读通知筛选。
- 服务重连后同步当前通知，并追踪通知移除原因。
- PII 清洗失败时不再回退保存原始正文。
- 支持通知详情、标记已读、清空和导出。

### 语音识别

- 统一 AudioRecord 采集和音源回退逻辑。
- 完善 DashScope、Step、Whisper 和 OpenAI Realtime 的配置与错误反馈。
- 增加有限重试、断线状态和录音取消处理。
- 语音识别错误会直接显示在输入栏，不再静默失败。
- 文件转录模式与实时麦克风入口分离。

### 数据与工作区

- 支持 Muse 原生 JSON、NDJSON、ZIP 以及第三方备份导入。
- 增加空备份保护、导入回滚、FTS 重建和 ZIP 条目安全处理。
- 工作区支持通过系统文件管理器导入具体文件，可一次选择多个文件。
- 重名文件自动编号，使用临时文件和原子改名保护导入过程。
- 增加文件大小限制和工作区路径安全边界。

### 稳定性与工程质量

- 修复性能分段计时错误，避免日志出现异常的超大耗时。
- 增强每日总结的前台补偿、时点占位、失败重试和进程恢复。
- 保留单一会话生成任务和工具预算状态来源，减少并发状态互相覆盖。
- 完成 Debug / Release 构建、单元测试、静态规则检查和 APK 签名验证。

## 升级提示

- 如果升级后系统无障碍列表中保留旧的 Muse 项目，请先关闭旧项目，再开启新的 `Muse UI 自动化`。
- 麦克风按钮只有在语音识别设置中选择实时 API Provider 并保存有效 API Key 后才会出现。
- Shizuku、Root、第三方 ASR 和云端 Provider 均需要用户自行安装、授权或配置；未配置时 Muse 会保留明确的不可用状态，不会伪造成功。
- 正式包提供 arm64-v8a、armeabi-v7a 和 universal 三种架构。

## 已知限制

- 不同厂商 ROM 可能会限制无障碍服务后台运行，需要在系统设置中允许 Muse 自启动或后台运行。
- DashScope、Step、Whisper 和 OpenAI Realtime 的实际识别能力取决于网络、服务端点和用户配置。
- Shizuku 相关能力需要设备安装并授权 Shizuku；未安装时不影响无障碍基础能力。
