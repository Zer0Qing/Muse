# 后台保活与进程恢复方案

本文记录 Muse 在“用户切出页面 / App 进入后台 / 进程被系统或用户强杀”时，如何保证模型生成继续或自动恢复。

## 适用场景

- 用户发送消息后立即切到桌面或其他 App，生成不应中断。
- 系统在后台回收进程，生成中任务应在下次启动时自动恢复。
- 群聊轮转、子代理任务等长任务同样依赖同一套前台服务与账本机制。

## 核心链路

### 1. 生成运行在应用级协程

`ChatGenerationManager` 使用 `appScope` 启动生成任务，不依赖页面或 ViewModel 生命周期：

- 按 `sessionId` 独立管理多个并发生成。
- `activeGeneration` 暴露当前活跃生成，供前台服务更新通知。
- 同一会话重入会取消旧任务，不同会话互不干扰。

### 2. 切后台时启动前台服务

`MuseApp` 同时监听 `ProcessLifecycleOwner.ON_STOP` 和 Activity 计数兜底，调用 `ChatViewModel.onAppBackground()`：

- 开启“后台继续生成”且存在活跃生成时，启动 `ChatGenerationService`。
- 服务在 `onCreate()` 立即 `startForeground()`，避免 Android 14+ 前台服务超时崩溃。
- 获取 `PARTIAL_WAKE_LOCK`，最长持有 10 分钟，防止 Doze 休眠中断网络。
- `onStartCommand` 返回 `START_STICKY`，进程被回收后系统有机会重建服务。
- 服务只做保活和通知，不重复执行生成逻辑。

### 3. 生成结束自动停止服务

`ChatGenerationService` 观察 `activeGeneration`：

- 生成结束后调用方发送 `ACTION_STOP` 或服务观察到 `isStreaming=false` 时停止。
- 停止时释放 Wakelock、取消通知、`stopForeground`、`stopSelf`。

### 4. Outbox 作为持久化生成账本

发送消息时先写入 `MessageOutboxEntity`，再开始流式生成：

- 账本在生成完成前一直保留。
- 生成完成、失败或取消时才删除，避免冷启动重复恢复。
- 进程被杀后，账本仍然存在于 Room，保证用户消息和待生成 assistant 占位消息可恢复。

### 5. 启动时恢复未完成生成

恢复入口有三处，全部幂等：

- `ChatViewModel` 初始化时调用 `recoverPendingGenerations()`。
- `ChatGenerationService.onCreate()` 调用同一方法，覆盖系统重建服务场景。
- `MuseApp.onCreate()` 也调用一次，覆盖冷启动场景。

恢复流程：

1. 查询残留 outbox。
2. 若用户消息缺失，先补写用户消息。
3. 切换到对应会话，补齐 assistant 占位消息。
4. 重新调用 `launchStream` 继续生成。
5. 生成完成后清理 outbox。

### 6. 会话焦点恢复(R-UI-02)

- “用户当前查看的会话 id”与“正在生成的会话 id”分离持久化(DataStore 两个独立 key:viewed_session_id / generating_session_id)。
- 切换/新建/退出 Agent 模式时写入查看焦点;启动流式时写入生成焦点,生成结束或用户停止时清除。
- 进程恢复时优先按查看焦点打开会话;outbox / generation checkpoint 重放只恢复消息与生成任务,不改写查看焦点。

## MuMu 实测

设备：MuMu 模拟器，Android 15，虚拟显示由 MuMu 动态分配。

### 切后台继续生成

```text
adb shell am broadcast -n io.zer0.muse/.debug.DebugGenerationReceiver \
  -a io.zer0.muse.debug.GENERATE --es text "长文生成请求"

adb shell am broadcast -n io.zer0.muse/.debug.DebugGenerationReceiver \
  -a io.zer0.muse.debug.BACKGROUND
```

预期日志：

```text
ChatVM: 应用切后台,启动前台服务保活
ChatGenService: service created & foreground started & wakelock acquired
OpenAIProvider: streamChat TTFB / first delta
ChatGenMgr: generation finished
ChatVM: outbox cleaned
```

实测结果：长文生成约 70 秒，期间前台服务持续运行，生成完成后服务停止、outbox 清理。

### 杀进程恢复

```text
adb shell am broadcast -n io.zer0.muse/.debug.DebugGenerationReceiver \
  -a io.zer0.muse.debug.SIMULATE_KILL \
  --es text "长文生成请求" --ez background true --el delay 3000
```

生成开始约 3 秒后进程被杀，随后重新打开 App：

```text
adb shell am start -n io.zer0.muse/.MainActivity
```

预期日志：

```text
ChatVM: 待恢复生成: 1 条
ChatVM: 视觉辅助[跳过]
OpenAIProvider: streamChat POST ...
ChatGenMgr: generation finished
ChatVM: outbox cleaned
```

实测结果：进程被杀后残留 1 条 outbox，重启自动补用户消息并恢复生成，完成后自动清理账本。

### 群聊账本重放

```text
adb shell am broadcast -n io.zer0.muse/.debug.DebugGenerationReceiver \
  -a io.zer0.muse.debug.SEED_GROUP_GENERATION --es chatId "debug-group" --es text "测试群聊恢复"

adb shell am force-stop io.zer0.muse
adb shell am start -n io.zer0.muse/.MainActivity
```

预期日志：

```text
GroupChatScheduler: 待恢复群聊生成: 1 条
GroupChatScheduler: 群聊 debug-group 不存在,跳过轮转
```

实测结果：账本在进程被杀后仍保留，重启自动拾起；目标群聊不存在时会安全跳过，不会误生成。

## 注意事项

- 前台服务 Wakelock 最长 10 分钟，超长生成仍依赖 START_STICKY 和 outbox 兜底。
- 用户关闭“后台继续生成”后，切后台会主动停止前台服务。
- 恢复流程是幂等的，重复启动不会重复发送用户消息或重复生成。
- MuMu 的虚拟显示 ID 会动态变化，自动化输入时需以 `dumpsys window displays` 的实际 ID 为准。
