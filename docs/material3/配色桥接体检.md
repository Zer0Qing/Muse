## 1. 实现查完：**没有缺陷**，而我的第一判断是错的

我看到实现里没映射 `inverseOnError`（新版 Material3 有这字段），差点"顺手补上"。
用 `javap` 读这版 `ColorScheme` 的真实 getter 集合：

```
androidx.compose.material3:material3-android:1.4.0-alpha04
→ 36 个 getXxx()，其中没有 inverseOnError
```

实现正好映射 36 栏，注释里"Compose 这版还没有 fixed 系列色，故不映射"也是实话。
**教训：库的字段面用工具查（`javap`/构建），别凭对别的版本的记性改代码** ——
凭记性就会写出引用不存在字段的编译错误，或者更糟：以为自己在修 bug。

## 2. 真缺陷在测试：名字承诺"全部"，实际只查 15/36

原用例叫 `all fields map from dynamic scheme`，断言只有 15 栏（42%）。
这类**名不副实的测试比没有测试更糟**：后来的人会以为这里已经钉住了。

改成 `assertEveryRoleMapped(scheme, colorScheme)`：

- **清单来自 `javap` 的 getter 集合**，不是照抄实现里写了哪些 —— 照抄的话"实现漏一栏"永远测不出来；
- 写成"栏名 → (期望, 实际)"三元组，而不是两份平行列表：两份手写的清单一旦错位，
  断言就在比不相干的两栏，看着全绿其实什么都没测；
- **明、暗各测一次**：实现里有 `buildDark` / `buildLight` 两套构造器。
