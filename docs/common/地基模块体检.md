## 1. `TextTruncation`：契约破了，而且注释还在撒谎（提交 `8e39531a`）

它是上下文预算的守门人：`ConversationCompressor.MAX_MSG_CHARS=1500`、
`ContextCompressTransformer.MAX_COMPRESS_MSG_CHARS=1500`、
`ToolOrchestrator.TOOL_RESULT_PREVIEW_CHARS=4096`、`HostWebSocketGateway.preview(text, limit)`。

### ① "截断后长度 ≤ maxLength"以前不成立

- `tail()`：**保留 `maxLength` 个字符之后又拼上约 50 字的省略标记 ⇒ 每次必然超**。
  而 `ToolOrchestrator` 的工具输出预览正是走它；
- `headTail()`：小预算下也超（头尾按 0.4+0.4 分完，标记没地方放）。
  生产里现有的四个预算（1500/1500/2000/4096）恰好不触发，但
  `preview(text, limit)` 的 limit 由调用方任意给 —— **传 120 拿到 139 是真实可达的**。

现在：先按**原文长度**给标记预留上界（标记里的数字位数随原文规模增长，
`omitted` 可以接近整段原文，而不是 ≤ `maxLength` —— 我第一版就按 `maxLength` 估，
被"永不超过上限"的循环测当场抓出：上限 41 拿到 42），剩余才是正文预算；
预算小到放不下标记时**退化为不加标记的纯截断** —— 宁可少一句说明，
也不交付比上限更长的文本。

### ② 类注释写"按**字节**切分"，实现与参数文档都是按 UTF-16 char

`maxLength`、`originalLength`、`omittedLength` 全是 `String.length` 口径（一个 emoji 算 2）。
这种谎会让人把 4096 当 4KB 去卡网络帧 / DB 列 / 通知长度 —— 本会话已经被过期注释骗过一次
（`SubagentRunner` 的"默认 120s"注释 vs 实际 240s）。注释现在明确写"char 口径"，
并用测试把这个单位钉死（`"😀😀😀"` 的 `originalLength` 必须是 6）。

### 新测试 8 例

`截断后的长度永不超过上限（headTail / tail）`（20..600 逐档扫）、
`tail 以前每次都超上限——回归钉子`、`标记放不下时退化为纯截断且不超限`、
`切分不切断代理对`、`未超限与非法上限原样返回`、
`省略量口径诚实且头尾不重复`（标记里写的数字必须等于 `Result.omittedLength`，
头是原文的开头、尾是原文的结尾）、`长度是 UTF-16 char 口径`。

### 我自己的两个错（都被测试当场抓住）

1. **第一版预留上界估错**：以为 `omitted ≤ maxLength`。循环测的"永不超过上限"直接红了
   （上限 41 → 42），才改成按 `text.length` 估。**"给个大概的上界"不算保证。**
2. **测试夹具自己造了孤立代理**：`longText()` 用 `setLength(n)` 硬截样本池，
   可能正好切在 emoji 中间 —— 于是"实现留下孤立代理"是**夹具的错**。
   改成整份拼接不硬截，并把"尾部保住"断言改成对原文结尾断言。
   这是本会话第一次假红源自 fixture 而不是 product，值得单独记。

## 2. `ErrorMessage`：契约只有一句话在守，还留着危险死码（提交 `af5f93b7`）

### ① 删掉 `Throwable.toErrorMessage()`（全仓 **0 引用**，连测试都没用）

它是"临时把异常归类"的启发式，其中一条是：

```kotlin
is IllegalArgumentException -> ErrorMessage.ValidationError.INVALID_FORMAT
```

而这个仓库里 `IllegalArgumentException` 是 `require(...)` 抛的 —— 消息**本身就是原因**
（`submitted text must not be blank`、`a render row must contain a message or chunk`…）。
把它一律归成"输入格式不合法"，等于**精心写下的原因被抹掉**，还顺手把系统侧的不变量违例
说成是用户的输入问题 —— 这正是本会话在暂停超时、审批拒绝、麦克风那几处反复修过的形状。

它现在没人调用，所以删掉不是"少了一个功能"，而是**少了一个等着被误用的陷阱**。
若将来真要做异常归类，得保留原始消息而不是换成模板文案。

### ② 迁移指南的背景段是过期的（实测已核对）

文件头写"v1.90 在 ai/memory/app 三层留下约 **800 处** `// TODO i18n`"。
实测 `Select-String 'TODO i18n'` 在 `app`/`ai`/`memory` 三个模块**现在是 0 处**。
留着旧数字会让后来的人以为还有一场大迁移。现在改成写结构性原因
（`ai`/`memory` 是独立 Gradle 模块，拿不到 app 的 `R.string`）。

### ③ 查出来的事实：英文 `defaultMessage` **不会**漏到用户眼前

`ErrorMessage.kt` 的注意事项写"[defaultMessage] 必须为英文（避免 locale 缺失时显示空白）"，
我担心这会让我上一轮在 `:ai` 修的"用户看到英文兜底"重演。读了 app 侧的
`ErrorMessageMapper.toLocalizedString` 才确认：**穷尽 `when` + 全部走 `R.string`**，
新增子类不补分支就编译失败；英文只进 `toLogString()`。已把这条写回注释，
并用测试钉住"所有 `defaultMessage` 不含中文"（否则会变成日志中文 + 界面另一套中文的双份口径）。

### 新测试 5 例（钉的是契约，不是行为）

| 用例 | 守的是什么 |
|---|---|
| `错误码不可变更——改名或删项都会红在这里` | 注释里那句"code 一旦发布不可变更（UI/日志/埋点/服务端联调都引用）"以前**只有一句话在守** |
| `每个错误码只出现一次` | 一一对应 `error_<code>` 的命名约定 |
| `defaultMessage 只进日志所以一律是英文` | 双份口径 |
| `限流错误的重试等待只在真有值时进元数据` | 上游没给 `retryAfter` 就不许编一个 |
| `日志串包含码与兜底文案` | 日志格式 `[ERR:code] message` |

## 3. `Logger`：脱敏承诺只做了一半（提交 `0375cb2c`）

KDoc 写着"避免敏感信息输出到 Logcat 或日志文件"，实测 `Throwable` 是**原样**流向三份出口：

| 出口 | 未脱敏的后果 | 谁会拿到 |
|---|---|---|
| `Log.w/e(tag, safeMsg, t)` | Android 连 `Caused by` 一起原样打印 | 接设备的 Logcat |
| `muse.log` | `stackTraceToString(t)` 直接写文件 | **要从真机回捞、导出到设备之外** |
| `dispatchToSink(…, t)` → `DebugLogStore` | 转字符串后显示在 DebugScreen、**并写进导出文件**（其 KDoc 只声明 message 已脱敏） | 应用内可见 |

现在 `w`/`e` 各构造一份 `sanitizedThrowable(t)` 三处共用：保留类名与消息、调用栈、因果链
（每层都脱敏），因果链**展开成文本而不挂回原 cause** —— 挂回去等于让 Android 再打印那条未脱敏消息；
链长上限 `MAX_CAUSE_DEPTH = 8`（`internal`，测试引用同一个数）。

### 两处真实漏匹配是测试抓出来的

1. **JSON 凭据完全没盖住**：`"access_token":"zzz-secret-9999"`。`KV_CRED_REGEX` 要求键名后紧跟
   `=` 或 `:`，而 JSON 是**引号再冒号**。注释却明写"分隔符 `[=:]` 兼容 JSON 中的冒号" ——
   又一条**自称做到的假注释**（与本轮 `Logger` 的 100KB、`:ai` 的"默认 120s"同一类）。
2. **裸 `key=…`**：只有 URL 的 `?key=`/`&key=` 被覆盖，`sort key=abc` 漏了。

同时钉住**不误伤**：`cache monkey=keepme sort=ok` 必须原样留着 —— 脱敏把正常内容吃光，
日志就没用了，那是另一种伤"用户使用方便"。

### 另外两条

- **`private` 就是没人测的原因**：`sanitizePii` / `sanitizedThrowable` 原先 private，
  **同模块测试也读不到 private**，所以这组复杂正则一直没被钉过。放开 `internal`（不扩 public）。
- **证据边界如实写**：`:common` 只有 junit、**没有 Robolectric**，所以"三份出口真的拿到脱敏视图"
  无法在 `:common` 单测（要触发 `android.util.Log`）。证据是代码读查 + `:app` 全量 0 失败；
  真测需要给 `:common` 加 Robolectric，那是独立决定，没顺手塞进来。
- 顺带修掉两处"rolling 100KB"的过期数字（常量 `1_000 * 1024` ≈ 1MB），改成引用常量名。

新测试 6 例：五类个人标识（逐条断言标记出现**且**原值消失）、凭据四种写法、
正常内容不被误改、堆栈保留而消息脱敏（还断言栈顶类名不变）、不挂回原 cause、链长有上限。

验证：`:common` **51 例 / 0 失败**（45+6）、detekt 0；`:app` 799 / 4576 / 0、
`:memory` 414 / 0、`:miniphone` 377 / 0、`:ai` 487 / 0。

## 4. 查过、没动的两处（避免下次重复排查）

- **`ProcessWriteGate`（35 行）**：`end()` 是无条件清闸，若调用方写成
  `try { begin(); … } finally { end() }`（不看 `begin()` 返回值），第二个恢复请求会在
  第一个替换窗口还没结束时把闸放开 → 在途写丢失 / WAL 与已删附属文件不一致。
  **实测 5 处调用点全是安全写法**：`BackupService` 两处与启动恢复用
  `require(begin()) { "…请勿重复操作" }`（拿不到就抛，不会进 `finally`），
  `MuseApp` 是 `claimed = begin()` 自旋到拿到才 `end()`。**所以不改**；
  这条留在文档里是因为它约束的是**未来**的调用方。
- **`ErrorMessageMapper`（app 层）**：穷尽 `when`、编译期强制同步、全部走 `R.string`。设计过，不动。

## 5. 脱敏对表结果与 `sk-proj-…` 缺口（提交 `a7ecd450`）

上一版清单里那句"脱敏口径分叉"这轮对完了。**两套规则互不包含**：

| 目标 | `PiiEngine`（19 条 Regex） | `Logger`（原 8 条） |
|---|---|---|
| 手机号 / 邮箱 / IPv4 / 银行卡（含 4-4-4-4） | ✅ | ✅ |
| 身份证 18 位 | ✅ | ✅ |
| 身份证 15 位（老式） | ✅ | ❌ → 本轮补 |
| 裸密钥形状 `sk-…` / `AKIA…` / `gsk_` / `ghp_` / `glpat-` / `xoxb-` | ✅ | ❌ → 本轮补 |
| PEM `PRIVATE KEY` 整块 | ✅ | ❌ → 本轮补 |
| 中文地址 / 姓名 / SSN | ✅ | ❌（**故意不补**：日志里抹掉姓名地址会吃掉排查要用的上下文，聊天与记忆链路已有 `PiiEngine` 兜住） |
| `Authorization: Bearer …` / `x-api-key:` | ❌ | ✅ |
| URL `?key=…` | ❌ | ✅ |
| JSON `"access_token":"…"` / 裸 `key=…` | ❌ | ✅（本轮补） |

`Logger` 注释里那句"与 `app.privacy.PiiGuard` 对齐"—— **对齐只存在于注释**：
`Logger` 全文对 `PiiEngine`/`PiiGuard` 的引用只有那一条注释，没有任何代码引用。
本轮把两边的差异写进两边的注释，不再靠"看起来一样"。

### 对表挖出一个更值钱的缺口：`sk-proj-…` 从来没被抹掉

`PiiEngine` 的 api_key 规则原本是 `sk-[a-z0-9_]{20,}` —— **字符类里没有连字符**，
于是 OpenAI 项目钥匙 `sk-proj-…`、Anthropic `sk-ant-…` 在第一个 `-` 处断掉，整条不匹配。

影响面是**核实过的**（不是推测）：

- `FactStore` 有 7 处 `PiiGuard.scrub(entry.fact)`，那是**存进事实库之前**最后一道
  → 用户在聊天里贴一把 `sk-proj-` 钥匙，会**原样写进长期记忆**；
- `SessionSummaryManager.mask(convText)` 是**发给模型前**的掩码
  → 这把钥匙**没被掩码，等于原样进入模型上下文**，还会留在摘要里；
- `MemoryAutoSaveScheduler.mask(...)`、`ChatStreamCoordinator.mask(...)`、
  `ChannelInbox.scrub(...)` 同理。

修法：`sk-[a-z0-9_-]{20,}`（`Logger` 与 `PiiEngine` 各一处）。
两侧都留**反向用例**：`sk-foo`、`sk_short` 这类正常写法必须原样留着 ——
否则脱敏会把记忆与日志里的普通内容吃掉，那是另一种伤使用方便。

测试：`:common` 从 51 → **55 例**（`LoggerSanitizeTest` 3 例 + `PiiEngineTest` 记忆侧 1 例；
后者还断言 `detected` 里出现 `api_key`，让"抹掉了"和"报告了"同时成立）。

## 6. `Perf` 与 `FileSizeFormatter`：地基件第一次有测试（提交 `a11ef0cc`）

### `Perf` 的耗时以前用挂钟相减

`track` / `trackSuspend` / `Timer` 全是 `System.currentTimeMillis()` 相减。挂钟会被 NTP 校时、
用户改时间、休眠唤醒拉动，于是埋点可能给出**负数或荒谬巨大**的耗时 —— 而这些数字进的是
ANR 诊断（`snapshotRecent()`）与性能报表，不是"日志里看看就算了"。

现在耗时走 `System.nanoTime()`，而 `PerfRecord.timestamp` **仍走挂钟** —— 那个字段表达
"什么时候发生"，本来就该是挂钟。这个分工写进注释并钉进测试。
（`track`/`trackSuspend` 是 inline，只能用公开 API，所以是直接除 1e6，没引私有 helper。）

其余部分是查过的、没问题的：`recentRecords` 有 50 条环形裁剪、sink 有 try-catch 隔离、
还专门给"不会落盘的快埋点"加了 `annotate`（否则 `chat-first-token` 这种几百毫秒的量
在日志里查不到）—— 这三样现在也都有测试守着。

### `FileSizeFormatter`：`1024 MB` 这种写法

四舍五入能把 `1023.96 MB` 推成 `1024.0`，以前原样显示 `1024 MB`，用户看的就是"为什么不是 1 GB"。
现在圆完到 1024 就进位到下一级单位。其余口径（1024 进制、一位小数、B 级不带小数、
到 TB 封顶、数字与单位一个空格、0 与负数都写 `0 B`、小数点固定 `Locale.US`）
本来就写在类注释里，**这次是第一次有测试守着**，包括把系统区域设成 de-DE 也必须是 `1.5 KB`。

### 为什么这两个件一直没测试

`:common` 的 `build.gradle.kts` 没配 `testOptions.unitTests.isReturnDefaultValues`，
而 `android.util.Log` 在单测里是 stub —— 任何走到 `Logger`/`Perf` 的用例都会因 `Log.d`
抛 "Stub!"。所以此前的 51 例全是纯函数用例。按 app / memory / miniphone / ai
四个模块的既有做法补上这一行（只影响单测行为）。

## 7. 两处脱敏合成一处真源（提交 `fe1708c8`）

§5 的矩阵读完就知道：**两份规则互不包含，留着就一定会再漂**。
事实也是这样 —— `sk-proj-…` 那次是**两边同时漏**（我给 `Logger` 补裸密钥形状时，
才在 `PiiEngine` 里发现同一个洞）。

合并做法：

- `PiiEngine` 里把日志需要的 7 条模式提成**具名 val**，`rules` 改引用它们
  （同一文件内也去掉 7 份重复字面量）；
- 新增 `PiiEngine.scrubForLogs(text)`，再加 3 条从 `Logger` 搬来的传输形状凭据
  （header / 键值 / URL query）；
- `Logger.sanitizePii` 变成**一行委托**，自带那 10 个正则 val 全删：
  `Logger.kt` **342 行 → 247 行**。名字与 `internal` 不变，三份出口照旧走它。

**刻意保留的不对称**已经写成注释 + 测试：日志不抹姓名与中文地址
（记忆里必须抹，日志里抹掉会把排查要用的上下文一起吃掉）。
以前这条只存在于口头，现在有人"顺手统一"会立刻红。

**替换顺序照搬、KV 正则逐字搬**：我写脚本时一度把 KV 那条"改写"成两个分支，
那会移动捕获组编号让 `$1` 指错位置 —— 发现后改回原样。**合并不顺手改语义。**

验证方式的关键是**数量不变**：`:common` 68 → **69 例 / 0 失败** ——
原有 `LoggerSanitizeTest` 6 例（裸密钥、PEM、15 位身份证、左右括号、`sk-foo`/`monkey=` 反向不误伤）
在委托后**逐条仍绿**，这就是"行为没变"的证据而不是我的说法；
`:memory` 414 / 0（`rules` 改引用具名 val 后记忆行为不变）、`:app` 802 / 4596 / 0。
