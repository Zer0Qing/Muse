# 小手机与 Agent 协作：细化路线

目标：**全面优化细化小手机功能，以及 agent 协作的所有相关**。
本文只写**量出来的事实**与据此排出的顺序，不写愿望。

## 0. 现状盘点（2026-11-04 实测）

| 面 | 规模 | 测试 |
|---|---|---|
| `:miniphone` 模块 | 169 文件 / 30,373 行（ui\chat 25、ui\shell 13、db dao+entity 18、moments 7、work 4） | 41 个测试类 / **309 例全绿** |
| 宿主能力 `MiniPhoneHost` | 接口 8 项能力 | **8 项全部有真实实现**（`AppMiniPhoneHost` 471 行） |
| Agent 协作（app 侧） | SubagentRunner 832、TeamWorkflowExecutor 752、MultiAgentSettingsPage 923、SubagentTool 440、DelegationChainCard 474、SubagentTaskListCard 568、DelegationConfirmDialog 388、AgentDmScreen 254、DelegationContract 204、DelegationChainTracker 230… | 8 个测试类（SessionStore / PauseManager / Access / Runner / TaskAsync / TeamWorkflow / DelegateBrief / SkillDelegate） |

一个需要记下来的教训：我一度断言"宿主 8 项能力只实现了 4 项"，那是**grep 只匹配 `override fun`、漏了 `override suspend fun`** 造成的假警报。
以后凡是"某能力没人实现"这类结论，必须先确认搜索模式覆盖 `suspend`，否则会把好代码当缺陷去"修"。

## 1. 本轮已修（入口隐藏契约）

小手机的可见性此前**只有注释在传达，而两处注释互相矛盾**：

- `FeatureFlags` 顶部写"不能只藏 UI 而留着路由"；
- `MINI_PHONE_ENTRY` 自己写"搜索仍能命中、链接仍能进入"；
- `ChatNavGraph` 留着"本版不对外发布"的旧注释；
- `ARCHITECTURE_MAP` 写着 `MINI_PHONE = false`、"当前不发版" —— 与代码（`= true`，模块与路由都在包里）相反。

真实设计是：**入口藏（首页 `MINI_PHONE_ENTRY`、设置 `browseVisible`），路由留（`MINI_PHONE`）**。
已做三件事：

1. 两处注释/文档按真实设计重写，并解释**为什么允许留路由**（模块在包里却裁掉路由，
   会让搜索命中与恢复的导航栈指向不存在的页面，比"能进但没入口"更难解释）；
2. 新增 `MiniPhoneVisibilityContractTest`（4 例）把契约钉成断言：
   首页过 ENTRY、设置过 `browseVisible && MINI_PHONE`、路由过 `MINI_PHONE` **且不得过 ENTRY**、
   `MOMENTS == MINI_PHONE`；
3. 验证：feature 族 4 例全绿，`:app:detekt` 仍为 18 条（零新增）。

## 2. 接下来的顺序（按"风险 × 可验证性"排）

### P1 协作 UI 四个面零测试 —— 最大的一块黑

`DelegationChainCard`(474) / `SubagentTaskListCard`(568) / `DelegationConfirmDialog`(388) /
`AgentDmScreen`(254) 在测试里**一次都没出现**。这是用户直接看的委派链与确认界面：
状态渲染错了没人知道。
做法：用已经打通的真机 Compose instrumentation 通道补渲染与交互测试
（本机 instrumentation 已验证可跑），断言点选具体：状态徽标、节点顺序、确认/拒绝后的落库。
验收：四个面各至少一组渲染断言 + 一组交互断言，`:app:detekt` 不上升。

### P2 小手机子系统的覆盖不均

`work` 4 个实现里 1 个没被测试提到、`ui\shell` 13 个里 4 个、`ui\moments` 7 个里 3 个。
先补**有行为后果**的那几个（调度与外壳生命周期），不补纯装饰。
验收：`:miniphone` 309 例基线上只增不减，新增例能指出具体行为。

### P3 语音链路两端一致性（已有不变式，但没测）

`supportsVoiceTranscription()` 与 `transcribeVoice()` 都转发给同一个 `OneShotAsrTranscriber`，
接口注释明确要求"两边的结论必须一致"。这条不变式**目前没有测试锁**，
将来任何一方加分支就会漂（表现为"麦克风能按、按完转不出字"）。
验收：一组假转写器参数化测试，断言两个出口在同一配置下同意或不同意。

### P4 协作语义的显式化

`DelegationContract`(204) / `DelegationPauseManager`(246) / `DelegationChainTracker`(230)
都有实现与部分测试，但"暂停点谁批准、批准几次、链最深几层"这些规则的**唯一出处是代码**。
做法：写成一页规格 + 用测试钉住每个边界值（深度上限、并发上限、暂停恢复语义）。
验收：规格文档与测试互指，改任一边界必须同时改两处。

### P5 发布面上的说法与实际一致

小手机与网页版属于"代码在、入口藏、发行材料不提"。每次发版要复核：
`manifest.json`/release notes 没写它们，而 `ARCHITECTURE_MAP`/`HANDOFF` 写清了为什么。
本轮已把第一条矛盾消掉，后续每次动旗标都要复跑 P1 的契约测试。

## 3. 明确不做

- 不把路由改成受 `MINI_PHONE_ENTRY` 控制（见 §1 的理由）；
- 不给小手机或协作 UI 补"截图级"快照测试 —— 渲染细节靠真机看，逻辑靠断言；
- 不在这一批动 `:app:detekt` 剩下 18 条结构性违规（另案，已有进度记录）。
